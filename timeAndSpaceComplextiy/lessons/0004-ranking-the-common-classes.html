Time & Space Complexity · Lesson 4

Ranking the Common Classes

The win: you can order the seven classes fastest-to-slowest without thinking, name a real algorithm for each, and read any growth chart — the "compare two approaches" muscle for interviews.

This lesson interleaves everything from Lessons 1–3. Mixing shapes together (instead of drilling one at a time) is harder now and sticks better later — it's how the recognition holds up under interview pressure.

1. The ladder, best to worst

Anchor phrase

"Can Little Nerds Not Quit Exams Fast" → Constant, Log, liNear, liNearithmic, Quadratic, Exponential, Factorial.

2. What each shape looks like

Two things to notice on the chart. Constants set the starting height, not the shape — an O(n) line with a big constant can start above an O(n²) curve, but the curve always overtakes it. And the crossover is often at small n: past a few dozen elements, the higher class has already won.

3. The interview heuristic: what n can each class handle?

Roughly a billion simple operations per second. If the expected input is n, these are the classes that finish in about a second:

If n is up to……this is fast enough
1,000,000,000O(log n), O(1)
10,000,000O(n), O(n log n)
~10,000O(n²)
~500O(n³)
~25O(2ⁿ)
~11O(n!)

This runs backwards too: if the interviewer says "n can be up to a million", they've just told you an O(n²) solution won't pass — you need O(n log n) or better. That's often the whole hint.

4. Interleaved practice — name the class

Work through each before checking. Say the class out loud, then the reason.

A: for i in 0..n { for j in 0..n { sum += grid[i][j] } }

B: for (let i = 1; i < n; i *= 2) { print(i) }

C: for i in 0..n { a() } then for j in 0..n { b() }

D: for i in 0..n { binarySearch(sorted, arr[i]) }

E: for (const k of ['a','b','c']) { total += counts[k] }

Interviewer: "n can be up to 1,000,000." What does that rule out?

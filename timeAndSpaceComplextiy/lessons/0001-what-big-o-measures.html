What Big-O Actually Measures

The win: after this lesson you can say precisely what O(n) means, and explain why O(500n) is the same thing.

1. It measures growth, not time

Big-O does not tell you how many milliseconds your code takes. That depends on the machine, the language, the JS engine, what else is running. Those numbers change; Big-O is meant to be the thing that doesn't.

Big-O answers one question: as the input gets bigger, how does the amount of work grow? The input size is called n (see glossary: input size). Work usually means "number of basic steps the algorithm performs".

Interview framing. Interviewers care about growth because real inputs get large. Code that is fine for n = 10 can be unusable at n = 1,000,000. Big-O is how you predict that without running anything. (Interview Cake)

2. Worked example: count the steps

Here are two JavaScript functions. Count how many times the core line runs, as a function of n = arr.length.

Function A — print every element

function printAll(arr) {
  for (let i = 0; i < arr.length; i++) {
    console.log(arr[i]);      // runs n times
  }
}

The loop body runs once per element: n times. If n doubles, the work doubles. That straight-line relationship is O(n) — "linear time".

Function B — print every pair

function printPairs(arr) {
  for (let i = 0; i < arr.length; i++) {
    for (let j = 0; j < arr.length; j++) {
      console.log(arr[i], arr[j]);   // runs n * n times
    }
  }
}

For each of the n outer iterations, the inner loop runs n times: n × n = n² steps. If n doubles, the work goes up four times. That is O(n²) — "quadratic time".

The counting recipe

  1. Pick the input size n.
  2. Find the operation that runs the most often.
  3. Write, in terms of n, how many times it runs.
  4. Simplify with the two rules below.

3. The two rules that turn a step-count into Big-O

Rule 1 — Drop the constants

O(2n), O(500n), and O(n/2) are all written O(n). A constant multiplier shifts the line's steepness but not its shape — it is still a straight line. Big-O only cares about shape.

Example: a loop that does 3 operations per element is 3n steps → still O(n).

Rule 2 — Drop the lower-order terms

O(n² + n) is written O(n²). For large n, the biggest term dwarfs everything else: at n = 1000, n² is 1,000,000 and the + n is a rounding error.

Example: one loop of n then a nested loop of n² is n² + n steps → O(n²).

Both rules exist for the same reason: Big-O describes behaviour as n approaches large sizes, where only the fastest-growing part matters.

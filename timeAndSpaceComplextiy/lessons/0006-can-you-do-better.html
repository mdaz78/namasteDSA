Time & Space Complexity · Lesson 6

"Can You Do Better?"

The win: when the interviewer asks this, you can name the bottleneck line, propose a faster approach, and state exactly what it costs in space. This is the last core skill in your mission.

"Can you do better?" is not a trick. It means: your brute force works — now find the one part doing the most work and make that part cheaper. You already have every tool for this from Lessons 1–5.

1. The move, in three steps

  1. State where you are. "This brute force is O(n²) time, O(1) space."
  2. Name the bottleneck. Which line or structure produces the dominant term? For O(n²) it's almost always an inner loop that searches.
  3. Make that operation cheaper with one of the three levers below, then restate the complexity and its new space cost.

2. Worked example: Two Sum

Given an array and a target, return the indices of the two numbers that add to target.

Brute force

function twoSum(nums, target) {
  for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) {   // ◄ the bottleneck
      if (nums[i] + nums[j] === target) return [i, j];
    }
  }
}

Step 1: O(n²) time, O(1) space. Step 2: the inner loop is a search — "does a matching partner for nums[i] exist later in the array?" That search is O(n), and we do it n times.

Step 3: make the search O(1)

The partner we want for nums[i] is exactly target - nums[i]. "Has this value been seen?" is a hash-map lookup — lever 1. 

function twoSum(nums, target) {
  const seen = new Map();                 // value -> index
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    if (seen.has(need)) return [seen.get(need), i];   // O(1), not O(n)
    seen.set(nums[i], i);
  }
}

Say it in the interview

"Brute force is O(n²) time, O(1) space — a nested loop checking every pair. The inner loop is really searching for target - nums[i], so I can store seen values in a hash map and look the partner up in O(1). That's O(n) time, at the cost of O(n) space for the map."

3. Second example: contains a duplicate?

ApproachTimeSpace
Compare every pair (nested loop)O(n²)O(1)
Add each to a Set, stop if already presentO(n)O(n)
Sort, then check adjacent elementsO(n log n)O(1)

Three valid answers with different trade-offs — and naming the trade-off is the point. If the interviewer says "no extra space", the sort version is your answer even though it's slower.

The pattern behind both examples: a nested loop whose inner job is a search is the #1 thing "can you do better?" is asking about. Hash map for membership, sort for order. Trading O(n) space to drop a factor of n from time is almost always the right call unless told otherwise.

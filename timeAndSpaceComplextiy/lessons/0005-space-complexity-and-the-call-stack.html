Space Complexity & the Call Stack

The win: you can state a solution's space complexity as a separate sentence — and you won't forget the recursion call stack, which is where interviewers catch people.

Everything so far was time. Space complexity uses the exact same rules — count as a function of n, drop constants and lower-order terms — but counts extra memory the algorithm allocates, not operations.

1. What counts, and what doesn't

  • Not the input. An array of n numbers passed in is the caller's memory. Space complexity is the auxiliary (extra) memory your algorithm adds on top.
  • A fixed set of variables → O(1), called "in place". Ten counters is still O(1) — a constant.
  • A new structure that grows with n (array, Map, Set, string being built) → O(n).
  • The recursion call stack → O(depth). This one is invisible in the code. Section 3.
  • The output is a judgement call — say your assumption out loud. Section 4.

2. Worked examples

O(1) space — your searchElement.js

function searchElement(arr, element) {
  for (let i = 0; i < arr.length; i++) {   // i is one number
    if (arr[i] === element) return i;
  }
  return -1;
}

One loop variable, no new structure. O(n) time, O(1) space. Say both.

O(n) space — a frequency count

function countEach(arr) {
  const counts = new Map();          // grows with the number of distinct items
  for (const x of arr) {
    counts.set(x, (counts.get(x) ?? 0) + 1);
  }
  return counts;
}

In the worst case every element is distinct, so counts holds n entries. O(n) space — you spent memory to get a fast O(n) time. That trade is the heart of Lesson 6.

3. The recursion call stack

Every function call that hasn't returned yet occupies a frame on the call stack: its parameters, local variables, and where to resume. Frames pile up as calls go deeper and pop off as they return. The deepest the stack ever gets is your space cost, even if each frame is tiny. 

function sumToN(n) {
  if (n === 0) return 0;
  return n + sumToN(n - 1);   // waits for the inner call before adding
}
sumToN(5);

The classic interview gotcha

Naive recursive Fibonacci is O(2ⁿ) time — but its call stack only ever goes n deep (it fully computes one branch before starting the other). So its space is O(n), not O(2ⁿ). Time and space are answered separately and are often different.

Loop vs. recursion

Your countDigits.js uses a while loop, so it holds a couple of variables → O(1) space. Rewrite it as a recursion that calls itself once per digit and it becomes O(log n) space (stack depth = number of digits). Same time, different space. A loop is usually the cheaper choice for space.

4. Does the output count?

If a function must build and return an array of n results, that array is O(n). Interviewers differ on whether "space complexity" includes the required output. The safe move: state it explicitly — "O(1) extra space, not counting the output array" or "O(n) space including the result". Either is fine; not saying which is the mistake.

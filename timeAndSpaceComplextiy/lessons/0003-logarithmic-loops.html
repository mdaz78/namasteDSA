Time & Space Complexity · Lesson 3

Logarithmic Loops → O(log n)

The win: you can spot the "cut the problem by a constant factor each step" pattern and name it O(log n) on sight — and explain why n = 1,000,000 takes only ~20 steps.

From Lesson 2: a loop that steps i++ runs n times → O(n). This lesson is about loops that don't step by one — they multiply or divide — and run far fewer times.

1. The one idea

O(log n) shows up when each step throws away a constant fraction of what's left — half of it, nine-tenths of it, doesn't matter which fraction. The question "how many times can I cut n down before there's nothing left?" has the answer log n.

2. Worked example: your countDigits.js

function countDigits(n) {
  if (n === 0) return 1;
  let digits = 0;
  n = Math.abs(n);
  while (n > 0) {
    n = Math.floor(n / 10);   // n loses a factor of 10 each pass
    digits += 1;
  }
  return digits;
}

A 5-digit number takes 5 passes. A 10-digit number takes 10. The number of passes is the number of digits, which is about log₁₀(n). In Big-O terms that is O(log n).

The base doesn't matter

This loop divides by 10, so it's log₁₀ n. Binary search divides by 2, so it's log₂ n. In Big-O both are just O(log n) — changing the log base only multiplies by a constant (log₂ n = log₁₀ n × 3.32…), and constants are dropped. Don't write the base.

3. The other shape: i *= 2

for (let i = 1; i < n; i *= 2) {
  doWork(i);
}

i goes 1, 2, 4, 8, 16, … — doubling until it passes n. Starting at 1 and doubling, it takes log₂ n steps to reach n. Same complexity, approached from the other direction: O(log n).

Whenever the loop variable is multiplied or divided (rather than + 1 / - 1), suspect O(log n).

5. The canonical example: binary search

function binarySearch(sortedArr, target) {
  let lo = 0, hi = sortedArr.length - 1;
  while (lo <= hi) {
    const mid = Math.floor((lo + hi) / 2);
    if (sortedArr[mid] === target) return mid;
    if (sortedArr[mid] < target) lo = mid + 1;   // throw away the left half
    else hi = mid - 1;                            // throw away the right half
  }
  return -1;
}

Every comparison discards half the remaining array. From n down to 1 in log₂ n comparisons → O(log n). This is the payoff for keeping an array sorted: lookups go from O(n) (Lesson 2's searchElement) to O(log n).

6. Combined: a loop of n around a log step → O(n log n)

for (let i = 0; i < n; i++) {      // n times
  binarySearch(sortedArr, arr[i]); // log n each
}

n iterations, each doing O(log n) work → O(n log n). This is the complexity of efficient sorting (merge sort, heap sort, Array.prototype.sort) — worth memorising as "the good sorting number".

7. Check yourself
